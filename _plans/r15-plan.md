# r15 plan: The deck (Opus planner, 2026-11-17)

Status: **approved under the owner's standing go-ahead (2026-11-17, "keep going with r15, ping me when merged").** Branch `release/r15` from main at 5e6d812 (r14.0). No stack, cluster or live run: every fact on a slide comes from `_plans/claims.md` (verified rows) or an example file.

## Approach

**Chosen: a pptxgenjs generator, with CNDP's layout around it.** CNDP has no source, so its decks are edited in place. This deck starts from nothing, so it gets the Python book's generator: code slides are read byte-exact from `examples/` with an anchored first line, so a code change upstream breaks the build. CNDP's surfaces are kept as Q7 requires:

- `text/` holds a Markdown copy of every slide, generated by `deck_text.py --write`. CI rebuilds the deck and fails on drift with `--check`.
- `edits/` holds the edit record: one file per change round (`edits/r15.0.md`, plus `r15.0-R1.md`, `R2.md` for validation repairs) listing slides changed and why. Mechanism: edit `sections/*.js`, rebuild, `deck_text --write`.
- `BUILD.md` is the build record (pins, build steps, QA, how to make an edit).

`lgtm-presentation/` holds: `Event-Driven-Patterns-with-Quarkus-and-Camel.pptx`; `package.json`, `package-lock.json`; `deck.js` (cover, assembly, `finish`) and `sections/01..09-*.js` (one module per section, disjoint owners); `deck-lib.js` (from the Python book, plus a JAVA/YAML language chip and `qrSlide`); `deck-helpers.js` (the skill's copy, dashes reworded, md5 recorded) and `assets/`; `render-png.sh`, `svg_to_png.py` (vendored from lgtm-diagram-generator), `notes.py`; `png/` (figure PNGs plus `qr-site.png`, `qr-hub.png`); `text/`, `edits/`, `BUILD.md`.

`deck_text.py`, `deck_fit.py`, `deck_render.sh` are adapted from CNDP into `scripts/`. `_plans/deck-evidence.md` maps each slide to its source page, claim ids, figure spec and code range (internal files may name chapters).

Rejected: in-place edits with `deck_edit.py` (binary diffs, no code anchoring); `text/` as the source (cannot carry layout); one deck per Part (Q7 says one); redrawing figures (specs are the authority); render check in CI (no brand fonts on runners); `pptxgenjs@^4` as in the EIP decks (floats).

## Deck design

- Audience: the PRD §2 readers (Java/Quarkus developers, Camel integrators, platform engineers, architects); not Kafka beginners.
- Length: one deck, target 119 slides (accepted 105 to 130), a three-hour session; agenda notes give a 90-minute path.
- Slide types: cover, agenda, divider, bullets (each pattern opens with a bold one-sentence definition), figure, code, table, QR.
- Notes floor: 90 words on content slides, 45 on cover, dividers and QR; `finish()` asserts the floors and notes count = slide count.
- Stand-alone: dividers carry a section name, never a number; captions name a service and file (`inventory-service · ReservationService.java`), never an example number; only the QR slide points to the site.
- Metadata: creator and company `PatternCatalyst`; cover byline "Pattern Catalyst", no personal name.

## Acceptance criteria

- One `.pptx` with 105 to 130 slides; notes on every slide at or above the floors; `finish()` asserts both.
- `validate.py` (decks, SVG cross-references, dashes) and self-test, voice ban tier 0 over `lgtm-presentation`, `deck_text.py --check`, `host_ids.py check`, site build all clean.
- 0 cross-reference or self-reference hits; the site pointer only on the QR slide.
- 14 code slides, each first line anchor-asserted against its example file at build time.
- Every figure PNG matches a fresh render of its committed SVG (`render-png.sh --check`); no figure drawn for the deck; 32 and ae regenerated, every other SVG byte-identical.
- QR codes decode to exactly the two URLs; both answer 200.
- `deck_fit.py` 0 flags on a full brand-font render; every slide PNG looked at.
- Every number in slides or notes has a verified claims id in `_plans/deck-evidence.md`.
- `npm audit` 0; lockfile committed; no `node_modules`; pptxgenjs pinned exactly; no global installs, no sudo.
- CI `deck` job passes, `content-ok` green; tag r15.0, notes-only release.

## Risks

| Risk | Response |
|---|---|
| `deck_text` heuristics misread pptxgenjs output (no title placeholder) | 1B tests on a two-slide fixture built by 1A; eyebrow and title from font size |
| Long Java lines shrink code below 11 pt | build fails; tighter range, recorded |
| A slide number drifts from the claims | evidence map plus the Opus spot check; cut rather than restate |
| Stand-alone regex false positives | fix the wording, never the regex, unless plainly not a cross-reference |
| Two builds differ beyond timestamps | pin builder date and ids; record in BUILD.md |
| Section authors overflow frames | step 3 sends the fix back to the owner |
| soffice profile or temp files in the repo | `LO_PROFILE` and output under `$TMPDIR` or the scratchpad |
